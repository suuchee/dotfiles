# amend 操作

直前のコミットを上書きする `git commit --amend` の使用条件、コミットメッセージの扱い、`--no-edit` の使い分けをまとめる。

## 使用条件

amend は以下の条件を満たす場合のみ使用する：

1. ユーザーが明示的に amend を指示した場合
2. 同じ変更（同じ目的・スコープ）に対するコミットである（セッション内でも別の変更が混ざる場合があるため、変更の同一性で判断する）
3. リモートに push 済みでない（force push が必要になるため）

## amend 時のコミットメッセージ

amend でも SKILL.md「コミットメッセージ - 起点とする差分」の原則に従い、`git diff HEAD~1` の最終差分を起点に書く。amend 前の古いメッセージに引きずられない。

amend は既存コミットの上書きであり、最終的なコミットには amend 前の変更も含まれる。差分の量や性質が変わったらメッセージも更新するのが原則。

## `--no-edit` を使ってよい場面・使ってはいけない場面

`--no-edit` は既存のメッセージを保持するオプション。**コミットの趣旨が変わらない場合のみ** 使う。

| 状況 | `--no-edit` | 理由 |
| --- | --- | --- |
| typo 修正・forgot ファイル追加など、コミットの趣旨が変わらない | OK | メッセージは変わらない |
| `git reset --soft` で複数コミットを統合した | NG | 古いコミットメッセージが残り、内容と乖離する |
| 別目的の変更を取り込んだ | NG | スコープが変わる |
| ファイルのリネーム・大幅な追加削除を加えた | 要判断 | 何が起きたかが重要なら更新 |

## よくある失敗

`git reset --soft <older-commit>` で複数コミットを HEAD に統合した直後に `--no-edit` で amend すると、**統合前の最初のコミットメッセージのままになる**。コミット内容は最新の差分なのにメッセージは古い意図のまま、という乖離が起きる。

統合 amend のときは必ず `git diff HEAD~1` で最終状態を確認し、新しいメッセージを書き起こす（`-m "..."` を明示する）。

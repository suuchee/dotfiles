# 対象視点で書く（作業者視点を混ぜない）

名前・タイトル・コミットメッセージ・コメント・本文は、対象（コード・機能・概念）に起きた変化を中心に書く。作業者の手元の動き（どこから持ってきたか・作業順・試行錯誤・AI に指摘された等）を混ぜない。書き手には自然だが、読者の問いには答えないため。

| 作業者視点 | 対象視点 |
| --- | --- |
| アーカイブから復元した | 不足していた参照ドキュメントを追加した |
| AI に指摘されたので修正した | 矛盾していた記述を修正した |
| `restore-from-archive`（ブランチ名） | `expand-git-skill-references` |
| `getUserFromMysql` / `tmp` / `processData` | `findUser` / `pendingInvoices` / `normalizeAddress` |

「なぜ」も作業者の事情（「念のため」等）ではなく、対象側の必要性（不足しているもの・解決したい問題・守るべき制約・防ぎたい失敗・読者への影響）として書く。時間で読者が変わるもの（コミットメッセージ・コメント）は、最も長く読む読者＝数ヶ月〜数年後の改修者を想定する。

例外: 作業者視点そのものが読者の問いに答える場合（自分用メモ・Runbook の手順・デバッグ記録・設計判断の経緯）は書いてよい。

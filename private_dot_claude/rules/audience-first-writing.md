# audience-first writing

人に読まれる名前・タイトル・本文・コメント・コミットメッセージは、読者がその場で知りたい問いに答えるために書く。書く前に「誰が・いつ・何のために読み、読後に何を判断・実行するか」を決める。読者が複数いるなら主読者を決め、時間で読者が変わるなら最も長く読む読者（コメントなら数ヶ月〜数年後の改修者）を想定する。

## 作業者視点ではなく対象視点で書く

失敗の多くは「作業者の手元の動き」（どこから持ってきたか・作業順・試行錯誤・AI に指摘された等）の混入で起きる。これらは書き手には自然だが、読者の問いには答えない。対象（コード・機能・概念）に起きた変化を中心に書く。

| 作業者視点 | 対象視点 |
| --- | --- |
| アーカイブから復元した | 不足していた参照ドキュメントを追加した |
| AI に指摘されたので修正した | 矛盾していた記述を修正した |
| `restore-from-archive`（ブランチ名） | `expand-git-skill-references` |
| `getUserFromMysql` / `tmp` / `processData` | `findUser` / `pendingInvoices` / `normalizeAddress` |

「なぜ」を書くときも、作業者の事情（「アーカイブに残っていたため」「念のため」）ではなく、対象側の必要性（不足していたもの・解決したい問題・守るべき制約・防ぎたい失敗・読者への影響）として書く。

例外: 作業者視点の情報そのものが読者の問いに答える場合（自分用メモ、Runbook の手順、デバッグ記録、設計判断の経緯）は書いてよい。

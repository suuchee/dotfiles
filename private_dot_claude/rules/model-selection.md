# サブエージェントのモデル選定

サブエージェントを呼び出すとき、各サブタスクにどのモデルと effort を割り当てるかの判断軸。呼び出し側（親）の能力ではなく、**そのサブタスク自体の難易度と失敗コスト**で決める。

## 原則

1. **既定は親モデルの継承。** 明確な理由がなければ下げない。下方への切り替えは呼び出し側が払う正確性リスクであり、コスト目的の暗黙のダウングレードはしない。
2. **効かせる軸は「難易度 × 不可逆性」。** 広く浅い作業は安い高速モデルで並列数を稼ぎ、深い推論・検証・不可逆な判断は強いモデルを維持する。
3. **検証は強モデルで。** 独立した検証・敵対的レビューは「新規コンテキスト」であることに価値があるのであって、安モデルである必要はない。むしろ強モデルで回す。
4. **effort が「どれだけ考えるか」の主軸。** モデルを固定したまま effort で深さを調整する。安いモデルへ落とす前に effort を下げる方を先に検討する。

## 割り当ての目安

| サブタスクの性質 | モデル | effort |
| --- | --- | --- |
| 広く浅い探索・並列読み取り（Explore 相当） | 安価・高速な下位モデル | low |
| 機械的・定型的な変換 | 中〜下位モデル | low〜medium |
| 通常の実装・調査 | 親と同じ（既定は最上位 Opus） | high |
| 難しい推論・設計判断・独立検証・敵対的レビュー | 親と同じ最上位（Opus / Fable）を維持 | xhigh〜max |

- effort は下位モデル（Haiku 等）では非対応で、渡すとエラーになることがある。下位モデルに割り当てるときは effort を指定しない。
- 最新の model ID・価格・effort 対応表・機能可用性は `claude-api` スキルを参照する（volatile なため本ファイルには載せない）。

## キャッシュ境界

同一ループの途中でモデルを切り替えるとプロンプトキャッシュが無効化される。別モデルを使いたいときは、ループ内で切り替えるのではなく**サブエージェントとして切り出す**（親ループは 1 モデルに固定したまま、サブタスクだけ別モデルに委任する）。

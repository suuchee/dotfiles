# サブエージェントのモデル選定

サブエージェント呼び出し時の model / effort 指定は**既定で省略**する（親モデル・セッション effort を継承。harness の推奨と同じ）。指定を検討するのは以下に触れるときだけ。

1. **コスト目的の暗黙ダウングレードをしない。** 下位モデルへの切り替えは正確性リスクであり、品質が結果に影響しない機械的・広く浅いタスクに限る。
2. **独立検証・敵対的レビューは親と同等以上のモデルを維持する。** 検証の価値は「新規コンテキスト」にあり、安くすることではない。
3. **モデルを変えるならループ内切替ではなくサブエージェントに切り出す。** 同一ループ途中のモデル切替はプロンプトキャッシュを無効化する。
4. **別ティアの採用（上位含む）を検討するときだけ**、最新の特性・価格・effort 対応・制約（refusal 等）を確認する。確認は `claude-api` スキルが正本だが、ロードが非常に重い（十数万トークン規模）ため親で直接読まず、**知りたい項目だけを返すサブエージェントに読ませる**（lookup 自体は機械的なので下位〜中位モデルで良いが、スキル本文が収まるコンテキスト長を持つモデルを選ぶ）。

- effort は下位モデル（Haiku 等）非対応で、渡すとエラーになる。下位モデルに割り当てるときは effort を指定しない。
